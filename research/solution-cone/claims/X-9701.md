## Findings and growth of spurious(N)

- **Main identity, verified exactly at every tested N:** `truncated-kernel-dim(N) = comps(N) = 2 + spurious(N)` for T (and `3 + spurious_U(N)` for the 3n−1 control). The truncated kernel dimension is NOT 2: the excess is entirely boundary artifact — every extra component was verified to (i) consist of vertices that reach 1 under the full map, and (ii) contain a vertex whose T-image lies above N.
- **Growth:** spurious(N)/N = 0.170, 0.167, 0.1666, 0.16665, 0.16667 at N = 100, 1000, 5000, 20000, 100000 — i.e. spurious(N) ≈ N/6, growing **linearly**, not vanishing. (Heuristic, not a claim: cut edges are the odd m ∈ ((2N−1)/3, N], and there are ≈ N/6 of these.)
- **Unplanned exact observation (T only, EMPIRICAL):** `spurious(N) = cut_edges(N)` at every tested N. Combined with the verified fact that each spurious component has ≥ 1 cut edge, this forces (in the tested range) that each spurious component has **exactly one** cut edge and the two genuine components ({0} and the 1-component) have **none**. The U-control shows this is not an artifact of the accounting: at N = 100, cut_U = 16 > spurious_U = 15, so for U a cut edge can sit inside a non-spurious component (or share one). This T-specific coincidence is a candidate for a separate provable claim (relate it to: every odd m > (2N−1)/3 has all in-window neighbors — 2m and possibly (2m−1)/3 — feeding a subtree that exits only through m); it is **not** proved here.
- **Takeaway for the solution-cone program:** naive truncation of the kernel of (I − F)* on [0,N] overcounts components by Θ(N); any truncated-spectral argument must subtract boundary-orphaned constraints explicitly, and the exact bookkeeping `dim = (#true components in window) + spurious` is the correct correction, validated on both T and the U control.

## Gap audit (author)

1) Definitional near-circularity in part (3): spurious(N) is computed as the number of truncated components containing neither 0 nor 1, so comps = 2 + spurious would hold vacuously once 4(c) is known. I mitigated this by separately asserting the two substantive facts — every spurious component is a subset of C1 (all its vertices reach 1 under the full map) and every spurious component contains a boundary-orphaned vertex (T(m) > N) — but a reader wanting 'spurious' defined purely intrinsically (components whose every path to their full-graph component exits [0,N]) should note I verified the exit property in the direction 'each spurious component has >= 1 cut edge', not the stronger per-path statement; for the tested T ranges the exact equality spurious = cut_edges closes most of this gap, but that equality is itself only observed, not proved. 2) Single test vector: parts (1)-(2) verify the coefficient identities on one deterministic pseudo-random integer vector rather than symbolically; since every checked identity is linear in a and the index maps (m -> T(m), k -> 3k+2, k -> 2k+1) are compared pointwise with generic-looking values, a coincidental collision masking an index bug is astronomically unlikely but not impossible (two wrong indices would need equal LCG states). A second seed or a symbolic check (a_i = i) would remove this; not run. 3) The exponent reduction j(n-2) mod 3 in the omega-filter uses omega^3 = 1 implicitly; this is standard but means the filter check exercises only the three residue classes of exponents rather than long omega-power products — the claim as stated (S(n) computed in Z[omega] equals 3*indicator) is still fully verified, but a hostile reading could say the 'filter' is only ever evaluated at reduced exponents. Also note Python's % on the negative value j(n-2) = -2j (for n=0,1) returns nonnegative residues, which is the intended mathematical mod — checked cases n=0,1 pass, so this is handled, but it is the kind of spot where a port to another language (C-style %) would silently break.
