# How the bounded return is certified

The imported unbounded localization theorem does not record where its witness occurs. The new proof reuses the ordinary path and exchange semantics and checks the height on each affine row at which a witness can be charged. The source data are PR197 commit `7ad81ec56947146fac854d2586651ca0c934a536` and the byte-exact PR146 descent certificate in its `directed-return/vendor/ReverseBasin.lean`.

For the 1-modulo-16 localization, a state stores the original affine row, the current row, and the list of previous rows known to carry the same ordered failure. A split refines **all** these rows by the same original ternary digit. At a nonunit both continuations are checked, since the true choice depends on the actual labels. A terminal certificate can use an earlier row. The ordinary path on that row is interpreted by `DirectedEleven.checkedSound`; every tripling position in that same path has both affine coefficients bounded by \(2^{22}\) times the original row. This controls every nonnegative value of its parameter, including its constant term. An \(11\bmod32\) witness exchanges to \(17\bmod48\) at height at most twice as large. Exiting already in \(17\bmod48\) returns the current defect directly. The resulting bound is \(2^{23}\) times the actual 1-modulo-16 input. Seventy-five independent finite decisions at ternary depth four, followed by their prefix tree, cover the entire initial row.

The second tree checks the 26 older descent leaves starting at every odd integer. Its ordinary portions use `DirectedEleven.runSound` with empty query lists. At a tripling position \(v=3a\), the code verifies \(a\) is odd and \(v\le2^{12}\) times the batch input. If the tripled input stays outside the basin, the path continues. If it enters the basin, a true 1-modulo-16 reverse failure at \(16a+1\) or \(32a+1\) follows from `NonunitExit.directed_successor`. Each is at most \(16v\). The preceding finite localization then gives a \(17\bmod48\) witness below the stated \(2^{40}\) bound. In the remaining case the entire batch ends at a strictly smaller positive nonbasin integer, so strong induction applies. Even inputs use ordinary halving.

The complete literal Lean data are embedded in `QuantitativeReturn.lean`. Run `python -B replay_quantitative_tables.py` from its directory to reconstruct the data from the original literal tables. The executable uses explicit exceptions, works under optimized Python and requires no external packages. It is a provenance check; Lean validates the row soundness and the numerical constraints independently of Python.
