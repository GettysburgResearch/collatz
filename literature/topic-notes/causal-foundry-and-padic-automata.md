# Causal Foundry and `p`-adic automata

## Exact closure viewpoint

Let `Q` be the parity-vector isometry and `Phi=Q^{-1}`. A Foundry operator `E` seeks

```text
Q(alpha)=E(alpha),
```

or equivalently

```text
alpha=Phi(E(alpha)).
```

If `E` is strictly causal, `Phi o E` is a `1/2`-Lipschitz contraction. Thus one fixed point exists and is computable.

The frontier is not existence but **ordinary integrality**:

```text
When is the unique fixed point eventually zero in binary?
```

## Operator hierarchy

### Constant/open-loop

`E` ignores its input. The fixed point is simply the inverse parity image of one prescribed word. This is the classical ordinary-marker/survivor problem.

### Finite delay

Output bit `k` depends on a bounded window of earlier input bits. These operators are naturally finite-state or finite-memory and can be represented as Mealy transducers.

### Finite-state unbounded delay

A finite automaton may summarize all previous digits in one state. Anashin's van der Put criterion gives an exact recognition route.

### Counter/pushdown

An unbounded counter or stack can generate nonautomatic output while retaining a finite local transition rule. This is the natural overlap with PR #3's counter-stack and PR #20's active height directives.

### General computable causal

The fixed point remains computable, but no finite structural certificate is automatic.

## Useful exact questions

1. If `E` is affine over `Z_2`, can `alpha_E` be solved explicitly?
2. If `E` is finite-state and strictly causal, is `alpha_E` necessarily algebraic over `Q_2`, rational, or neither?
3. Which van der Put coefficient patterns force an eventually-zero fixed point?
4. Can one certify nonintegrality by proving infinitely many nonzero output blocks?
5. Can a finite-state operator generate a fixed point whose parity code clears the PR #20 factor-complexity lower bound?
6. Does input feedback evade the automatic-frequency obstruction, or merely transfer the complexity into the fixed-point digits?

## First tractable theorem program

For every chosen operator class:

```text
A. write the exact contraction;
B. derive the fixed-point digit recurrence;
C. classify rational fixed points;
D. prove or refute eventual-zero digits;
E. compute factor complexity of the resulting parity code;
F. compare with the supercritical density condition.
```

Start with affine and two-state strictly causal operators. These classes are small enough for symbolic elimination and exhaustive automaton minimization, while already testing whether feedback creates genuinely new integrality behavior.

## Nonapplication boundary

A finite-state **operator** does not imply a finite-state closed-loop orbit: the fixed point contains unbounded arithmetic state. Conversely, a highly complex fixed point can be generated by a simple contraction. Therefore automaticity results must be applied to the produced digit/parity sequence, not merely to the rule defining `E`.
